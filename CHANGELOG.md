# История изменений

## 0.0.3 — 16 ноября 2026 года

Ускорение интерфейса, исправление резервного подключения и улучшенная диагностика поверх версии 0.0.2.

### Быстродействие интерфейса

- Убрана двухсекундная задержка загрузки встроенной страницы WebView2: служебный адрес `tgws.local` заменён на `tgws.example`.
- В трёх локальных замерах медиана времени от показа окна до готовности интерфейса сократилась с **2546 до 567 мс** — в **4,49 раза**, или на **77,7%**. Повторное открытие уже созданного окна заняло **29 мс**.
- Добавлены измерения `UI_STARTUP` и `UI_REOPEN` в интеграционный тест настоящего WebView2, а также проверка повторного открытия без перезагрузки страницы и перезапуска прокси.

Числа относятся к тестовой Windows x64-машине и не гарантируют одинаковое ускорение на всех компьютерах. Методика, условия и отдельные прогоны приведены в [отчёте о запуске UI](docs/ui-startup.md).

### Подключение и диагностика

- Исправлен выбор резервного TCP-маршрута: зависшие основные маршруты больше не расходуют весь срок выбора. Туннели получают общий бюджет 8 секунд, затем резервный TCP — отдельные 8 секунд.
- В диагностику добавлена проверка **CF WS without TLS (probe only)**. Она помогает обнаружить сети, где TLS-маршруты недоступны, но WebSocket на порту 80 работает.
- При успешной пробе диагностика объясняет, как явно включить существующий режим `no_secure`. Сама проверка не меняет настройки и проверяет установку транспорта, а не доставку сообщения Telegram.
- Переключатель режима переименован в **Без TLS (WebSocket, порт 80)**. Описание поясняет, что MTProto остаётся зашифрованным, а дополнительный TLS-слой и H2 отключаются. По умолчанию TLS остаётся включённым.
- Добавлены отдельные ручные тесты CF WebSocket с TLS и без него: анонимный запрос `req_pq_multi` проверяется по ответу `resPQ` и совпадению nonce.
- Добавлены регрессионные проверки отмены зависших маршрутов и запуска резерва; успешный основной маршрут не запускает резервный TCP.

В проверенной сети соединения с TLS и прямыми адресами Telegram завершались таймаутами, а CF WebSocket без TLS передавал сообщения. Это рабочий вариант для данного сетевого сбоя, а не гарантия обхода любых ограничений.

### Документация

- README переоформлен в стиле sparkmc: заголовок по центру, скриншот, навигация и динамические бейджи лицензии, последнего релиза, CI и скачиваний.
- Добавлены рекомендации при недоступности Telegram, описание режима без TLS и ограничения транспортных проб.
- Обновлены описание маршрутизации, команды сетевых тестов и отчёт об ускорении UI.

### Проверки

- Пройдены тесты Rust с desktop и без него после сетевых изменений.
- После ускорения UI пройдены Windows-тесты и интеграционный тест настоящего WebView2: загрузка ресурсов, мост с Rust, сохранение настроек, запрет внешней навигации, скрытие и повторное открытие окна.
- Сборка и проверка типов фронтенда, форматирование Rust, Clippy на Rust 1.96 и Windows x64 release-сборка прошли.
- Реальная доставка анонимного сообщения Telegram подтверждена через CF WebSocket без TLS. Прямые TCP/WS-пробы в этой сети завершились ошибками доступности.
