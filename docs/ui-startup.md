# Скорость открытия интерфейса

Проверено 16 ноября 2026 года на Windows x64 с установленным системным WebView2. Сжатие ресурсов и изменение дизайна не применялись.

## Изменение

Встроенная страница WebView2 использовала адрес `https://tgws.local/index.html`. В трёх запусках HTML уже был получен примерно за 33 мс, но загрузка CSS начиналась только спустя две секунды. JavaScript и стили передавались из памяти за миллисекунды.

Адрес заменён на `https://tgws.example/index.html`. После этого двухсекундная пауза исчезла. Конкретный внутренний механизм WebView2 не установлен. Разработчики Microsoft описывали дополнительные попытки разрешения имён для перехваченных запросов и рекомендовали домен `.example` в [обсуждении WebView2Feedback #3398](https://github.com/MicrosoftEdge/WebView2Feedback/issues/3398). Это основание для выбора адреса, а не доказательство того, какой внутренний компонент задерживал этот запуск.

Ресурсы по-прежнему встроены в EXE и выдаются через WebResourceRequested. Проверки навигации и источника сообщений используют новый адрес. Системные проверки безопасности WebView2 и браузерные параметры не менялись. Контроллер создаётся при открытии окна и сохраняется после скрытия.

## Измерения

Каждый прогон использует отдельный тестовый процесс и новый профиль WebView2. Измеряется время от вызова `Ui::show()` до появления главной страницы, получения состояния Rust и доступности кнопки открытия Telegram. Это время готовности интерфейса, а не замер вывода кадра на физический экран. Сборка тестов — debug, Rust 1.100; кеш ОС не очищался, перезагрузка компьютера между запусками не выполнялась.

| Прогон | До, мс | После, мс |
| --- | ---: | ---: |
| 1 | 2546 | 618 |
| 2 | 2526 | 557 |
| 3 | 2549 | 567 |
| Медиана | **2546** | **567** |

По медиане готовность интерфейса наступает в **4,49 раза быстрее**, ожидание уменьшилось на **77,7%**. DOMContentLoaded сократился с 2028–2041 до 94–114 мс. В отдельной проверке повторное открытие сохранённого контроллера заняло 29 мс; `performance.timeOrigin` не изменился, перезагрузка документа и перезапуск прокси не происходили.

Значения относятся к этой машине и сценарию. Первый запуск после перезагрузки, другой Runtime, антивирус или медленный диск могут дать другое время.

## Проверка

```powershell
cargo test --locked --bin TgWsProxyPlus system_webview -- --ignored --nocapture
```

Тест печатает JSON-строки `UI_STARTUP` и `UI_REOPEN`. Кроме измерений, он проверяет загрузку встроенных ресурсов, работу Preact и моста, сохранение настроек, запрет внешней навигации, размеры страниц, скрытие окна и повторное открытие без потери контроллера. Конфигурация пользователя в нём не участвует.
