# Проверка интерфейса 0.0.2

Проверка версии 0.0.2, 29–30 октября 2026 года. Windows x64, Rust 1.96, Node.js 24.16; профиль `release`, `opt-level=z`, fat LTO, один codegen unit, статический CRT.

## Размер

| Компонент | Размер |
| --- | ---: |
| Прежний EXE 0.2.1 на этой машине | 1,303,040 байт |
| Новый Windows x64 EXE | 1,425,408 байт (1.359 МиБ) |
| Разница | +122,368 байт (+9.4%) |
| Встроенные HTML, CSS и JavaScript без сжатия | 63,837 байт (62.3 КиБ) |
| Бюджет Windows EXE | 2 МиБ |

SHA-256 EXE: `ae6f2eee680d6a56d5cfe3ab66dbf13b3c4cec13f10ef3ffbca932185e8a52dd`.

WebView2 Loader связан статически. `WebView2Loader.dll`, Node.js, Tauri и Chromium в пакет не входят. EXE импортирует системные библиотеки Windows; проверка `scripts/inspect_binary.py` прошла. Установленный WebView2 Runtime, его кеш и память отдельных процессов в размер EXE не включены.

Интерфейс создаётся при открытии окна. При обычном запуске в трее запускаются Win32-оболочка и сетевое ядро; WebView2 не создаётся. После скрытия уже открытого окна контроллер сохраняется, чтобы быстро вернуться к настройкам и не терять несохранённые поля. Закрытие окна не означает немедленную выгрузку всех процессов WebView2.

## Компактный интерфейс

Окно по умолчанию — 660 × 520 логических пикселей вместо 1000 × 840, площадь уменьшена на 59%. Минимум — 580 × 460. Размеры учитывают системный DPI.

Дизайн переработан по референсу: узкая боковая навигация, тёмный серо-бирюзовый фон, тонкие разделители, поля с небольшим скруглением и нейтральные кнопки. Убраны зелёные индикаторы, повторяющиеся сообщения о работе, декоративные квадраты, знак со стрелкой и подпись автора. На главной — адрес, порт, копирование ссылки, действия Telegram, счётчики и журнал. Ошибки запуска показываются отдельно. Светлая тема сохранена.

Главная и настройки помещаются при стандартном размере без прокрутки. Остальные параметры доступны с вертикальной прокруткой. Все пять вкладок проверены на отсутствие горизонтального переполнения при минимальном размере. Эти проверки выполнены в настоящем WebView2.

Перед выпуском повторно выполнены сборка и проверка типов Astro, rustfmt, Clippy, тесты Rust с desktop и без него, интеграционный тест WebView2 и проверка установки обновления с откатом.

## Проверки

- Astro: сборка и проверка типов без ошибок и предупреждений; бюджет ресурсов соблюдён.
- `cargo fmt --all -- --check` и `cargo clippy --locked --all-targets -- -D warnings` — успешно.
- `cargo test --locked --all-targets` — 53 теста пройдены. Ручные сетевые проверки и бенчмарки по умолчанию пропускаются.
- `cargo test --locked --all-targets --no-default-features` — 49 тестов пройдены на Windows без desktop-оболочки.
- Настоящий системный WebView2: загрузка встроенных файлов, работа Preact и моста с Rust, сохранение светлой темы без перезапуска ядра, сохранность несохранённых полей при обновлении состояния.
- Через интерфейс проверены отклонение порта 0 без изменения файла и перенос слушателя на другой свободный порт. После закрытия окна слушатель продолжает работать.
- Неизвестная команда моста отклоняется; внешняя навигация отменяется.
- `tests/update_install.py`: установка с подтверждением готовности и откат при неудачном запуске — успешно, на отдельных тестовых EXE.
- Встроенные кадры ICO совпадают с `icon.ico`.

Кадры `assets/screenshots/overview.png` и `settings-light.png` получены из настоящего WebView2 с отдельными конфигурацией и портом. Нулевые счётчики на них соответствуют отсутствию клиентского трафика.

Перетаскивание окна и клики мышью по трею вручную не проверялись. Оконные сообщения, закрытие и события трея проверены программно. Один WM_LBUTTONUP вызывает открытие Telegram; двойное нажатие не дублирует запуск и не показывает настройки. В тесте внешний запуск клиента заменён счётчиком.

## Открытие Telegram

ЛКМ по значку трея вызывает открытие Telegram сразу, без ожидания двойного клика и без повторного добавления прокси. Если видимое окно клиента уже существует, приложение выводит его вперёд. Иначе используется заранее найденный Telegram.exe; зарегистрированный `-workdir` сохраняется. Другие аргументы из реестра не исполняются. Если прямой путь неизвестен, остаётся системный обработчик `tg://`.

Ссылка `tg://proxy` оставлена отдельной кнопке подключения и пункту меню. Время до полной готовности Telegram не измерялось: оно зависит от клиента, диска и состояния сессии. Процент ускорения для реального клиента не заявляется.

## Обновления и нумерация

Обычная сборка включает проверку обновлений. `TGWS_REVIEW_BUILD=1` остаётся дополнительным режимом для разработки без проверки релизов.

При переходе с прежней 0.2.x нужно вручную заменить EXE: SemVer считает 0.0.2 более ранним номером. Настройки из существующего файла сохраняются. После установки 0.0.2 следующие версии сравниваются обычным способом.
