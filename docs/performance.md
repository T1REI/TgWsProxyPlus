# Замеры производительности 0.2.0

Сравнение выполнено 23 октября 2026 года на одной Windows x64 машине, Rust 1.96.0. Сборка: `opt-level=z`, fat LTO, один codegen unit, встроенный CRT. Это локальные измерения; они не предсказывают скорость конкретной загрузки Telegram.

## Разбор пакетов и пересылка

Команда:

```powershell
cargo test --release --locked --test benchmarks --test h2_windows -- --ignored --nocapture --test-threads=1
```

| Проверка | Реализация 0.1.0 | Реализация 0.2.0 |
| --- | --- | --- |
| Пик запрошенных выделений при разборе пакета 4 МиБ | 20 МиБ | 12 МиБ |
| Шифрованная пересылка через in-memory duplex | 11,52 МиБ/с | 11,73 МиБ/с |
| Получение 4 МиБ по H2 при задержке управляющего чтения 30 мс | 589,5 мс | 183,5 мс |

Разбор пакета выполнялся порциями 32 КиБ. Аллокатор-обёртка учитывает запрошенные байты, включая временное перекрытие выделений при росте буферов; исходные входные данные исключены. Это пик выделений конкретного алгоритма, а не RSS приложения. Экономия 8 МиБ, или 40%, получена благодаря удалению полной копии открытого транспортного пакета.

Тест пересылки проверяет содержимое 32 МиБ в каждом направлении, включая AES-CTR и backpressure. Приведена медиана пяти чередующихся прогонов старого цикла с буфером 64 КиБ и нового с буфером 32 КиБ. Разница 1,8% мала и не доказывает ускорение в интернете. Тест проверяет непосредственно ядро пересылки, без TLS, UI и рейтинга маршрутов.

H2-тест сравнивает окна потока 256 КиБ и 1 МиБ при окне соединения 4 МиБ. Сервер задерживает управляющие чтения на 30 мс, передача локальная; приведена медиана трёх чередующихся прогонов. Полученное ускорение 3,21 раза относится только к этому сценарию. Проверена целостность всех байтов ответа. Это не модель полной задержки интернет-соединения.

## Размер EXE

Windows x64: 0.1.0 — **1 218 560 байт**, 0.2.0 — **1 251 840 байт** (около 1,19 МиБ). Дополнительные возможности и новая иконка увеличили размер на 33 280 байт, или 2,7%.

Проверены профили оптимизации `z` и `s`; `s` оказался больше. Компактный программный AES экономил только 1 КиБ и был отклонён ради скорости на процессорах без аппаратного AES. В итоговой сборке сохранён `z`; уменьшить EXE относительно 0.1.0 с добавленными возможностями не удалось. Упаковщики исполняемого файла не используются.

## Память и CPU в простое

```powershell
python scripts/measure_resources.py path/to/v0.1.0.exe target/release/TgWsProxyPlus.exe --output tests/results/resources-v0.2.0.json
```

Отдельные консольные процессы, без клиентов, `pool_size=0`, `cfproxy=false`, проверки обновлений отключены. Прогрев 1 секунда, наблюдение 3 секунды; медиана трёх процессов для каждой версии. Использованы Windows GetProcessMemoryInfo и GetProcessTimes.

| Показатель | 0.1.0 | 0.2.0 |
| --- | --- | --- |
| Working set | 8 589 312 байт | 8 613 888 байт |
| Private bytes | 1 609 728 байт | 1 601 536 байт |
| CPU в интервале наблюдения | 0,0% | 0,0% |

Потребление в простое практически одинаковое; снижения RSS или CPU этим тестом не установлено. Нулевой CPU означает отсутствие измеримого прироста в коротком интервале при доступной точности таймера. Это не измерение GUI или активных загрузок. Уменьшение числа фоновых пробуждений и закрытие неиспользуемых соединений проверены в коде и тестах пула; влияние на энергопотребление отдельно не измерялось.

## Проверки

42 локальных теста проходят с Windows-интерфейсом и без него; форматирование и Clippy проходят для обоих наборов features. Отдельно прошли три ручных бенчмарка и побайтовая проверка всех 11 кадров `icon.ico` в PE-ресурсах финального EXE.

Две внешние пробы к Telegram DC2 завершились ошибками: TCP connect timeout и недоступность прямого WS-маршрута. Это не успешная проверка реального Telegram. Доступность резервных публичных доменов и скорость файлов/изображений требуют измерений в сети пользователя. Работа нового окна настроек визуально в этом прогоне не проверялась.
